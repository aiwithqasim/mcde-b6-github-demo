=== Test 2: invalid marks update (out of range) ===
  [REJECTED] Invalid marks 150 for Ali: must be between 0 and 100.
  Marks unchanged: 85, Grade still: A

=== Test 3: another student, valid update ===
  [OK] Sara's marks set to 55 -> Grade C
  [OK] Sara's marks set to 65 -> Grade B
  get_marks() = 65, get_grade() = B

=== Extension: direct access to __grade ===
  ali._marks          -> 85  (works: protected, convention-only)
  ali.__grade         -> AttributeError: 'Student' object has no attribute '__grade'
  ali._Student__grade -> A  (name mangling workaround)
  Explanation: Python renames __grade to _Student__grade behind the scenes,
  so external code cannot access it directly. This prevents accidental access
  but is NOT true security (it can still be read via the mangled name).

=== Extension: why double underscores are not true security ===
  Double underscores only trigger name mangling (__balance -> _BankAccount__balance).
  It hides the attribute from casual access, but anyone can still read it via
  acc._BankAccount__balance. Real security requires language-level enforcement
  or cryptographic measures, not name mangling.
  acc._BankAccount__balance = 6500  (proof it is still reachable)

########## Q5.py ##########
=== Dispatcher with original three channels ===
  [EMAIL]    To: user@example.com | Body: Your order has been shipped!
  [SMS]      To: +92-300-1234567 | Text: Your order has been shipped!
  [PUSH]     To: mobile-app | Alert: Your order has been shipped!

=== WhatsAppNotification added WITHOUT changing notify_all ===
  [EMAIL]    To: user@example.com | Body: Your order has been shipped!
  [SMS]      To: +92-300-1234567 | Text: Your order has been shipped!
  [PUSH]     To: mobile-app | Alert: Your order has been shipped!
  [WHATSAPP] To: +92-300-1234567 | Chat: Your order has been shipped!

=== Where does polymorphism occur? ===
  In notify_all(): the loop calls .send(message) on each object without
  knowing its concrete class. Each class provides its own implementation
  of send(), so the same call produces channel-specific behaviour.
  This is duck typing / polymorphism in action - new notification classes
  work with the dispatcher as long as they implement send(message).

########## Q7.py ##########
=== Circle (radius 5) ===
  area      = 78.5397
  perimeter = 31.4159

=== Rectangle (width 4, height 6) ===
  area      = 24.0000
  perimeter = 20.0000

=== Attempt to instantiate Shape directly ===
  TypeError: Can't instantiate abstract class Shape without an implementation for abstract methods 'area', 'perimeter'
  Explanation: Shape is abstract (inherits ABC and declares @abstractmethod),
  so Python refuses to create instances of it. Subclasses must implement
  area() and perimeter() before they can be instantiated.
